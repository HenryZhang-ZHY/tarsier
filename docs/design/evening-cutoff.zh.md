# 设计：下机时间，以及重做「休息」页

[English](evening-cutoff.md) · **简体中文**

状态：已实现 · 2026-10-08。实现和本文有出入的地方记在 §9。

## 1. 问题

晚上过了某个时间还在用电脑，当晚就睡不好。用户心里清楚该停在几点，但到了那个时间手头总有事，一不留神就过去了。

tarsier 现在只管白天的节奏：连续工作多久该休息。它不知道一天在什么时候该结束。

## 2. 目标

- 用户设一个时间，tarsier 在这个时间到来前提醒一次，到点后用遮罩告诉用户：时间到了。
- 用户想继续用，写一句要做什么就可以继续，不设门槛、不限次数。
- 每晚几点停下的、延长时写了什么，都记下来，在「休息」页上和白天的节奏放在一起，让用户自己看出规律。
- 借这个机会，把「休息」页和背后的统计从零重做：从「给用户打分」改成「把作息照给用户看」。

### 不做

- 不在遮罩上提供关机、睡眠这类操作。看到提醒后电脑怎么处理，由用户自己决定。
- 不按星期几设置不同规则，每天是同一个时间。
- 不做防作弊：设置随时可改，改了马上生效；退出 tarsier 也没有任何惩罚。
- 不调显示器亮度，也不调色温。
- 这一版不做「昨晚睡得怎么样」的晨间反馈，以后另议。

## 3. 原则

这几条来自讨论，也是后面每个细节的取舍依据：

1. **tarsier 是帮用户养成习惯的，不是监管用户的。** 它提醒，然后尊重用户的决定。
2. **不预设用户下一步做什么。** 只说明现在的情况，不替用户选动作。
3. **作息每天都一样。** 只有一个时间，不分工作日和周末。
4. **用事实说话，不打分。** 告诉用户「21:52 停下的」，而不是「C 级，62 分」。

## 4. 下机时间

### 4.1 名字

讨论时一直叫它「宵禁」，产品里不用这个词：宵禁是别人强加的。界面上叫**下机时间**（英文 *Evening cutoff*），设置项写成一句话：

> 每天 [21:00] 以后不用电脑

### 4.2 设置

放在**设置 → 休息**分区的下半部分，和休息节奏并列，因为两者都是作息。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `evening.enabled` | `false` | 是否开启 |
| `evening.cutoff` | `"22:00"` | 下机时间，`HH:MM`，可选范围 12:00–04:59 |

界面上用一个时间输入框，由两个数字框（时、分）组成，沿用现有的 `NumberField`。

**默认值为什么是 22:00。** 睡眠医学给的建议都是相对上床时间而言的，没有一个统一的钟点：美国睡眠医学会（AASM）建议睡前 30–60 分钟关掉电子设备，美国国家睡眠基金会建议至少提前 30 分钟，能做到的话提前 2 小时。所以 22:00 只是一个起点：它对应 23:00 上床、提前一小时。设置项下方用一行小字说明这个依据，并且不另加「上床时间」这个设置项：

> 睡眠专家建议睡前 30–60 分钟停用屏幕。可以从你平时上床的时间往前推一小时。

下面这些是常量，不放进设置里：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `HEADS_UP` | 15 分钟 | 提前多久提醒 |
| `EXTENSION` | 15 分钟 | 选择继续使用后，多久再提醒 |
| `DAY_START_HOUR` | 05:00 | 一天从这个时间开始，下机时间也在这时结束 |
| `WRAP_UP_GRACE` | 5 分钟 | 下机时间后这么久之内停下，仍然算按时，见 §5.3 |

### 4.3 一晚的流程（以 21:00 为例）

```
20:45            21:00                        21:15 (若继续)        05:00
  │ 提前提醒       │ 遮罩出现                     │ 遮罩再次出现          │ 结束
  ▼               ▼                              ▼                     ▼
──┼───────────────┼──────────────────────────────┼─────────────────────┼──
```

**20:45：提前提醒。** 主显示器右下角出现一张小卡片，写着「21:00 下机，可以开始收尾了」，并显示倒计时（「还有 14 分钟」）。卡片不抢焦点，一直留到 21:00，到点后淡出，接着下机遮罩淡入。卡片右上角有一个 ×，用户点了它就关掉，当晚不再出现。

**21:00：遮罩出现。** 和休息遮罩一样，所有屏幕慢慢淡入一层遮罩，不抢焦点，点击穿透，但比休息遮罩更暗。遮罩上写：

> **21:00**（大字，当前时间）
> 到你给自己定的下机时间了。

主显示器的遮罩上还有一个小按钮**「继续使用」**，这是遮罩上唯一能点的东西。遮罩不会像休息遮罩那样被忽略后自动淡出，它会一直显示到 05:00，除非用户选择继续使用。

**继续使用。** 点击后，按钮展开成一个输入框：

> 还要用电脑做什么？ [____________] 回车确认 · Esc 取消

内容不能为空，除此之外不做任何检查。确认后遮罩淡出，15 分钟后再出现，这时会把用户刚才写的话显示出来：

> **21:15**
> 15 分钟前你说：「把部署脚本跑完」。

然后可以再次选择继续使用，次数不限。

### 4.4 边界情况

| 情况 | 行为 |
| --- | --- |
| 下机时间内开机、唤醒或启动 tarsier | 遮罩立刻出现；如果还在继续使用的 15 分钟内，就等到期再出现 |
| 提前提醒的 15 分钟内开机 | 立刻出提前提醒，当晚已经关掉过就不出 |
| 提前提醒时用户不在电脑前 | 卡片照样显示，回来就能看到 |
| 遮罩显示时用户离开或睡眠 | 什么都不做；回来时如果还在下机时间内，遮罩还在 |
| 继续使用的 15 分钟里电脑睡眠了 | 这 15 分钟按实际时间算，醒来后如果已经过了，遮罩直接出现 |
| 下机时间内修改设置 | 马上生效。改到更晚，遮罩淡出；关掉功能，遮罩淡出 |
| 早于 05:00 的下机时间，例如 01:00 | 生效时段是 01:00–05:00 |
| 休息提醒在下机遮罩显示时到期 | 不叠加显示，休息提醒视为被压下（suppressed），沿用现有逻辑 |
| 继续使用期间 | 休息提醒照常工作 |
| 托盘里「暂停提醒一小时」 | 只暂停休息提醒，不影响下机时间。下机时间有自己的「继续使用」 |
| `respect_fullscreen`（全屏时推迟提醒） | 对下机时间不生效。晚上看视频、打游戏，恰恰是这个功能要提醒的情况 |
| 独占全屏的游戏 | 遮罩可能盖不上去，记进[已知限制](../limitations.zh.md) |
| 不点「继续使用」，直接在遮罩下面接着用 | 可以，遮罩点击穿透。这种使用照样计入当晚的最后一次输入时间（§5.2），不另外处理 |

### 4.5 实现要点

- **新增纯逻辑模块 `src/evening.rs`。** 和 `breaks.rs` 一样每秒驱动一次，输入是「本地时间、配置、空闲秒数」，输出事件：`HeadsUp`、`Open`、`Close`。用户操作通过方法传入：`keep_using(reason)`。它不碰窗口，所以可以完全靠单元测试覆盖。
- **点击穿透和输入框的冲突。** 全屏遮罩照样点击穿透（`make_click_through`）。「继续使用」做成一个单独的小窗口，叠在主显示器遮罩的下方中间，这个窗口不穿透。点开输入框时，它才取得焦点，这是用户主动点的，所以不算抢焦点。
- **提前提醒卡片**：新的小窗口，参考 `switch_hud.rs` 的做法，但不取焦点。因为卡片上有 ×，它不能点击穿透；它只占屏幕角落一小块，可以接受。
- 遮罩的视觉风格和休息遮罩一致（全屏变暗层，使用当前皮肤的字体），但不是同一个组件：两者内容和交互不同，合在一起只会多出一堆分支。

## 5. 数据：重做 `stats.json`

### 5.1 一天从 05:00 开始

现在按午夜切分日期：00:30 结束的工作段算到第二天。这和人对「一天」的感觉不符，也会把下机时间之后的使用拆到两天里。新模型统一用 **05:00** 作为一天的开始，也就是下机时间的结束：

```rust
/// 一个时间戳属于哪一天：05:00 之前算前一天。
pub fn activity_day(ts: i64) -> NaiveDate
```

所有记录都按这个函数归到某一天。

### 5.2 每天记什么

```jsonc
{
  "version": 2,
  "days": {
    "2026-10-08": {
      // 这一天第一次和最后一次键鼠输入的时间（Unix 秒）
      "first_input": 1791432000,
      "last_input": 1791471120,
      // 工作段，和现在一样
      "sessions": [
        { "start": 0, "end": 0, "active_secs": 0, "target_secs": 0, "kind": "prompted" }
      ],
      // 每次休息提醒的结果，带时间，替换掉现在的三个计数
      "reminders": [
        { "at": 0, "outcome": "rested" }   // rested | snoozed | skipped | ignored
      ],
      // 下机时间：只在当天开启时出现
      "evening": {
        "cutoff": "21:00",                 // 当晚生效的设置，因为以后可能会改
        "extensions": [
          { "at": 0, "reason": "把部署脚本跑完" }
        ]
      }
    }
  }
}
```

- `last_input` 由控制器每秒计算：`now - idle`。只有比已记的值晚 60 秒以上才标记为需要保存，不然每秒都要写盘。
- 延长时写的理由只存在本机的 `stats.json` 里，不发到任何地方。

### 5.3 「守住」怎么算

这两条只用于在页面上陈述事实，不折算成分数。

- **休息节奏：** 当天没有一段连续工作超过目标的 150%。以默认的 50 分钟为例，这条线在 75 分钟。按现在的提醒规则推算：50 分钟时第一次提醒，没理会的话 60 分钟时淡出，65 分钟时第二次提醒，到 75 分钟又一次淡出。也就是说，推迟或者没理会一两次提醒，不算破坏节奏，手头的事总要收个尾；接连两次都顶着不休息，才算一段超长的工作。按比例而不是按固定分钟数来算，是为了让这条线随用户自己设定的工作时长一起变化。
- **下机时间：** `last_input` 不晚于 下机时间 + `WRAP_UP_GRACE`（5 分钟）。留这 5 分钟，是因为关机本身也要动鼠标；遮罩出现时手头那句话打完，也不该算没守住。
- 下机时间没开启的日子，这一条不统计；当天使用不到 15 分钟的日子，两条都不统计。

### 5.4 迁移

- 启动时发现没有 `version` 字段的旧版 `stats.json`，先原样另存为 `stats.v1.json`，再转换。
- `sessions` 按 `activity_day(session.end)` 重新归到对应的日子。
- `skips`、`snoozes`、`ignored` 三个计数没有时间，没法变成 `reminders`，丢弃。
- 积分、称号、等级本来就是从工作段算出来的，没有存储，直接随代码删除。

## 6. 重做「休息」页

### 6.1 去掉

- 0–100 的健康分、S–D 等级
- 积分和称号（从「Sedentary starter」到「Tarsier grandmaster」）
- 连续达标天数
- 托盘提示里的「今日健康 87」

删掉的理由：积分奖励的是「用得多」，称号只升不降，等级和健康分是一张成绩单。连续天数一旦中断就归零，一次失误抹掉之前所有的坚持，这正是监管的思路。

### 6.2 换成

页面从上到下分三块：

**1. 现在。** 保留现在的状态卡片：距下次休息多久、正在休息、已离开。开启下机时间后，再加一行：「下机时间 21:00，还有 2 小时 10 分钟」。

**2. 这一周的作息。** 页面的主体：七行时间轴，今天在最上面。

```
        06    09    12    15    18    21    24
今天     ·  ██ ███ ██  ███ ██ ██  │
周二     ·   ███ ████ ██ ███   ██ │▓▓  ← 21:40 停下 · 「把部署脚本跑完」
周一     ·  ██ ██ ███ ██ █████   ██│
…
```

- 横轴是一天中的时间。范围按这一周的数据自动调整：从最早的 `first_input` 到最晚的 `last_input` 和下机时间。
- 色块是工作段。超过目标 150% 的工作段用状态色标出，其余是中性色。
- 竖线是下机时间。下机时间之后的使用用不同的填充表示。
- 有延长记录的那一行，右边写着几点停下的、写过的理由；理由太长时截断，鼠标悬停显示全文。

**3. 两条习惯。** 每条一句事实陈述：

> 休息节奏：最近 7 天，有 5 天没有超长的连续工作。最长的一段在周二，94 分钟。
> 下机时间：最近 7 天，有 4 天按时停下。

**托盘提示** 改成：「tarsier · 23 分钟后休息 · 今天已工作 3 小时 20 分钟」。

### 6.3 移出这一页的

当前页面上的「今日工作段列表」可以去掉：它显示的信息，时间轴上已经有了。

## 9. 实现记录

实现基本按本文进行，下面这些地方有调整：

- **时间输入（§4.2）**：没有拆成「时」「分」两个数字框，而是一个输入框（`src/ui/time_field.rs`）。两侧的 −/+ 每次调 15 分钟，也可以直接输入，`2130`、`21`、`21.30`、全角冒号都能识别。不在 12:00–04:59 之间的值会退回原值。
- **状态机（§4.5）**：`src/evening.rs` 没有输出事件，而是一个纯函数 `status(现在, 下机时间, 今晚是否关过提前提醒, 最后一次继续使用的时间)`，返回此刻应该显示什么。控制器每秒比较一次，再开关窗口。这样睡眠唤醒、重启 tarsier、中途改设置都不需要单独处理。上一次继续使用的时间直接从 `stats.json` 里读，重启后 15 分钟照样算数。
- **遮罩再次出现时的文字（§4.3）**：写成「21:03 时你说：「…」」，用时刻，不用「15 分钟前」。睡了一觉醒来时，「15 分钟前」就不对了。
- **`last_input` 的保存（§5.2）**：内存里的值每秒更新，进入新的一分钟时才标记为需要写盘。
- **小窗口的边框**：Windows 11 会给小的浮动窗口自动加一圈细边框和阴影，看起来像卡片外面又套了一个空框。提前提醒卡片和「继续使用」窗口都去掉了这层（`platform::remove_frame`）。全屏遮罩不受影响。
- **这一周（§6.2）**：右侧单独一列「最后使用」，显示每天最后一次键鼠输入的时刻；今天这一格留空，因为它就是刚才。继续使用时写的理由完整显示在那一行下面，会自动换行，不截断，也不需要悬停。
- **习惯的措辞（§6.2）**：分母是这一周里实际算进来的天数和晚上，不固定是 7。例如「这一周用电脑的 6 天里，有 5 天没有超过 1 小时 15 分钟的连续工作」「这一周的 5 个晚上里，有 4 个按时停下」。
- **代码位置**：下机时间的窗口在 `src/ui/evening.rs`，「休息」页在 `src/ui/main_window/breaks.rs`，统计在 `src/stats.rs`。
